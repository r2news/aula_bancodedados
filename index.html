Módulo 1

De Dado à Decisão: os 4 Pilares

Antes de estudar banco de dados, é preciso entender quatro conceitos que caminham juntos. Esse é o ponto de partida de qualquer profissional de dados.

1
📊
Passo 01
Dado

Registro bruto, isolado, sem contexto suficiente para gerar sentido por si só. É o ponto de partida de tudo, mas sozinho pouco significa.

Exemplo: 8,5 — apenas um número, sem nenhum contexto.
2
🔍
Passo 02
Informação

Dado organizado e contextualizado. Quando o dado recebe nome, data, local e relação com outros dados, ele se transforma em informação útil.

Exemplo: A aluna Ana tirou 8,5 em Banco de Dados no 1º bimestre.
3
🧠
Passo 03
Conhecimento

Interpretação da informação para entender um padrão ou situação. Aqui começa a análise: comparamos, relacionamos e extraímos sentido.

Exemplo: Ana está com ótimo desempenho. Turma tem média de 7,2 — acima do esperado.
4
⚡
Passo 04
Decisão

Ação tomada com base no conhecimento produzido. É o destino de todo o processo: dados bem gerenciados levam a decisões mais inteligentes.

Exemplo: Professora propõe atividades avançadas para alunos acima de 8,0.
💡 Exemplo do cotidiano escolar A nota 6,0 é apenas um dado. Quando sabemos que João tirou 6,0 em Banco de Dados no primeiro bimestre, temos uma informação. Quando percebemos que a maioria dos alunos tirou entre 5,5 e 6,5, temos conhecimento para decidir se é necessária uma revisão do conteúdo.
🤔 Pergunta para reflexão Uma empresa consegue tomar boas decisões se seus dados estão incompletos, repetidos, espalhados ou desorganizados? Pense em exemplos da sua vida: quantas decisões erradas já foram tomadas por falta de dados confiáveis?

Módulo 2

O que é Banco de Dados?

Banco de dados está em praticamente tudo que usamos na vida digital. Entender o conceito muda a forma como você enxerga os sistemas.

Banco de dados é uma coleção organizada de dados, armazenada de maneira estruturada, para permitir cadastro, consulta, atualização, análise, proteção e recuperação das informações.

Pode ser algo simples como uma agenda de contatos, ou extremamente complexo como o sistema de um banco digital que processa milhões de transações por segundo.

📌 Definição essencial Banco de dados é a memória organizada dos sistemas. Ele armazena dados de forma estruturada para que pessoas e aplicações possam acessar informações com segurança e rapidez.

Módulo 3

SGBD — Sistema Gerenciador de Banco de Dados

O SGBD é o software que fica "no meio do caminho" entre a aplicação e os dados. Sem ele, não haveria controle, segurança nem organização.

💡 Ideia-chave O banco de dados guarda as informações. O SGBD gerencia como essas informações serão criadas, acessadas, protegidas, alteradas e recuperadas. Em inglês: DBMS — Database Management System.
🗂️

Criar estruturas

Permite criar tabelas, campos, chaves e relacionamentos. Define como os dados serão organizados antes de qualquer cadastro.

💾

Armazenar dados

Registra os dados de forma organizada, persistente e recuperável, garantindo que nenhuma informação se perca.

🔎

Consultar informações

Permite buscar dados com comandos SQL, filtros, ordenações e relatórios, com alta performance mesmo em grandes volumes.

🔐

Controlar acesso

Define quem pode ver, inserir, alterar ou excluir dados. Garante que cada usuário acesse apenas o que for necessário para sua função.

✅

Garantir integridade

Evita inconsistências, duplicidades e registros inválidos. Aplica regras que impedem que dados "sujos" entrem no sistema.

🛡️

Executar backup

Permite cópias de segurança automáticas ou programadas, garantindo recuperação em caso de falha, erro humano ou desastre.

Módulo 4

Modelos de Banco de Dados

Existem diferentes formas de organizar e acessar informações. Conhecer os modelos ajuda o profissional a escolher a estrutura mais adequada para cada projeto.

Mais utilizado

Modelo Relacional

Organiza os dados em tabelas compostas por linhas e colunas. Tabelas se conectam por meio de chaves, criando relações entre os dados.

Ideal para: cadastros de alunos, clientes, produtos, notas, vendas, matrículas — qualquer dado bem estruturado.
SGBDs: MySQL, PostgreSQL, SQL Server, Oracle.
Flexível

Modelo NoSQL

Armazena dados de forma flexível, sem estrutura rígida de tabelas. Ideal para dados variados, em grande volume ou com formato imprevisível.

Ideal para: redes sociais, big data, logs de sistema, chats, documentos e dados em tempo real.
Exemplos: MongoDB, Redis, Cassandra, Firebase.
Histórico

Modelo Hierárquico

Organiza os dados em formato de árvore, com relação pai e filho. Um registro "pai" pode ter vários registros "filhos".

Ideal para: estruturas de pastas, organogramas, classificações em níveis hierárquicos.
Exemplo real: estrutura de arquivos do Windows/Linux.
Espacial

Modelo Georreferenciado

Armazena dados relacionados à localização espacial e geográfica. Permite consultas por coordenadas, polígonos e distâncias.

Ideal para: mapas, rotas, fiscalização, planejamento urbano e localização de serviços públicos.
Exemplo: PostGIS (extensão do PostgreSQL).
Avançado

Modelo Orientado a Objetos

Armazena dados seguindo a lógica de objetos da programação. Integra-se naturalmente com linguagens OO como Java e Python.

Ideal para: aplicações com estruturas complexas que se integram diretamente com código orientado a objetos.
💡 Comparação simples Se os dados são bem estruturados — como alunos, cursos e notas — o modelo relacional funciona muito bem. Se os dados são variados, flexíveis e em grande volume — como posts de rede social ou logs de acesso — uma solução NoSQL pode ser mais adequada.

Módulo 5

Modelo Relacional: Tabelas, Linhas e Colunas

O modelo relacional é o mais utilizado no mundo. Para entendê-lo, basta compreender três conceitos simples: tabela, linha e coluna.

📋

TABELA

Representa um assunto principal do sistema, também chamado de entidade. Exemplos: Alunos, Produtos, Clientes, Pedidos.

↕️

LINHA (Registro)

Cada linha representa um único elemento daquela entidade. Cada aluno é uma linha; cada produto é uma linha.

↔️

COLUNA (Campo)

Cada coluna representa uma característica/atributo dos elementos. Nome, CPF, telefone, nota — cada um é uma coluna.

Módulo 6

SQL — A Linguagem dos Dados

SQL (Structured Query Language) é a linguagem padrão para criar, consultar, alterar e excluir dados em bancos relacionais. É a ferramenta mais importante no dia a dia de quem trabalha com dados.

SELECT
Consultar / ler dadosBusca registros de uma ou mais tabelas. O comando mais utilizado no trabalho diário com dados.
INSERT
Inserir novos dadosAdiciona um novo registro em uma tabela. Usado ao cadastrar um aluno, produto, cliente etc.
UPDATE
Atualizar dados existentesAltera informações já cadastradas, como corrigir uma nota, atualizar um telefone ou mudar o status de um pedido.
DELETE
Excluir registrosRemove registros de uma tabela. Use sempre com WHERE para não apagar tudo! Operação irreversível se não houver backup.
CREATE
Criar estruturasCria tabelas, bancos de dados, índices e outros objetos. É o primeiro passo ao implementar um banco de dados novo.
DROP
Apagar estruturasRemove tabelas ou bancos inteiros. Extremamente cuidado — é irreversível! Nunca use sem ter certeza absoluta do que está fazendo.

Exemplos práticos de código SQL

Consultar todos os alunos
-- Retorna TODOS os registros e TODAS as colunas da tabela
SELECT *
FROM alunos;

-- Retorna apenas nome, curso e nota (colunas específicas)
SELECT nome, curso, nota
FROM alunos;

-- Ordenar por nota do maior para o menor
SELECT nome, nota
FROM alunos
ORDER BY nota DESC;
💡 DicaO * significa "todos os campos". Em produção, prefira sempre nomear as colunas — é mais eficiente e claro.
Filtrar com WHERE
-- Somente alunos do curso de Banco de Dados
SELECT *
FROM alunos
WHERE curso = 'Banco de Dados';

-- Alunos com nota igual ou acima de 7,0 (aprovados)
SELECT nome, nota, situacao
FROM alunos
WHERE nota >= 7.0;

-- Alunos do curso de BD que estudam à noite
SELECT nome, turno
FROM alunos
WHERE curso = 'Banco de Dados'
  AND turno = 'Noite';
Inserir novo registro
-- Cadastrar um novo aluno
INSERT INTO alunos (nome, curso, turno, nota, situacao)
VALUES ('Lucas', 'Banco de Dados', 'Manhã', 8.0, 'Aprovado');

-- O ID é gerado automaticamente pelo banco (auto_increment)
-- Não precisa informar o ID manualmente

-- Inserindo múltiplos registros de uma vez
INSERT INTO alunos (nome, curso, turno, nota, situacao)
VALUES
  ('Marina', 'Redes', 'Tarde', 7.5, 'Aprovada'),
  ('Pedro', 'Informática', 'Manhã', 5.0, 'Recuperação');
Atualizar dados existentes
-- Corrigir a nota do aluno com ID = 2
UPDATE alunos
SET nota = 7.5, situacao = 'Aprovado'
WHERE id = 2;

-- ⚠️ PERIGO: sem WHERE, atualiza TODOS os registros!
-- UPDATE alunos SET situacao = 'Aprovado';  ← NUNCA faça isso

-- Atualizar todos os alunos com nota >= 7.0
UPDATE alunos
SET situacao = 'Aprovado'
WHERE nota >= 7.0;
⚠️ Atenção críticaSempre use WHERE no UPDATE e no DELETE! Sem WHERE, o comando afeta todos os registros da tabela — um erro gravíssimo em produção.
Criar uma tabela do zero
-- Criando a tabela alunos com tipos de dados definidos
CREATE TABLE alunos (
  id        INT AUTO_INCREMENT PRIMARY KEY,
  nome      VARCHAR(100) NOT NULL,
  curso     VARCHAR(80)  NOT NULL,
  turno     ENUM('Manhã', 'Tarde', 'Noite'),
  nota      DECIMAL(4,2),
  situacao  VARCHAR(20),
  criado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Tipos de dados mais comuns:
-- INT       → números inteiros   (id, quantidade)
-- VARCHAR   → texto variável     (nome, endereço)
-- DECIMAL   → números decimais   (nota, preço)
-- DATE      → data               (2026-05-28)
-- TIMESTAMP → data e hora        (2026-05-28 14:35:00)
-- BOOLEAN   → verdadeiro/falso   (ativo: true/false)

Módulo 7

Mecanismos de Filtragem de Dados

Filtrar dados significa selecionar apenas as informações que atendem a um critério específico. Isso evita trabalho desnecessário e permite análises muito mais precisas.

👤 Quais alunos foram aprovados?
WHERE situacao = 'Aprovada'
🌙 Quais alunos estudam à noite?
WHERE turno = 'Noite'
📊 Quais alunos tiraram nota ≥ 7,0?
WHERE nota >= 7.0
🔧 Quais chamados técnicos estão abertos?
WHERE status = 'Aberto'
📅 Vendas ocorridas em maio de 2026?
WHERE data BETWEEN '2026-05-01' AND '2026-05-31'
🏙️ Clientes de Belo Horizonte ou Ibirité?
WHERE cidade IN ('Belo Horizonte', 'Ibirité')
🔍 Clientes cujo nome começa com "Mar"?
WHERE nome LIKE 'Mar%'
💼 Na prática profissional Uma organização raramente precisa ver todos os dados ao mesmo tempo. Normalmente ela precisa localizar dados específicos: clientes de uma cidade, alunos de uma turma, produtos com baixo estoque, chamados abertos ou vendas de um período. O WHERE é o filtro que torna isso possível.

Módulo 9

Modelagem de Dados

Modelagem é o planejamento do banco antes da criação das tabelas. Como um arquiteto que desenha a planta antes de construir, o analista modela antes de programar.

"Um bom banco de dados nasce antes do primeiro comando SQL. Ele nasce no planejamento."
1

Modelo Conceitual

Visão geral das principais entidades e seus relacionamentos, sem se preocupar com detalhes técnicos. É a "ideia em alto nível".

ExemploUm sistema escolar tem: Aluno, Curso e Matrícula. Um aluno pode estar matriculado em um ou mais cursos.
2

Modelo Lógico

Transformação das ideias em tabelas, campos, chaves e relações. Define como os dados serão estruturados, mas ainda sem detalhes do SGBD.

Tabela Aluno: id, nome, turno
Tabela Curso: id, nome, carga_horaria
Tabela Matricula: id, id_aluno, id_curso, data
3

Modelo Físico

Implementação real no SGBD escolhido, com tipos de dados específicos, índices, restrições e comandos SQL reais.

CREATE TABLE aluno (
  id    INT PRIMARY KEY,
  nome  VARCHAR(100),
  turno VARCHAR(10)
);

Chaves Primária e Estrangeira

🔑

Chave Primária (PK)

Campo que identifica de forma única cada registro de uma tabela. Não pode se repetir, não pode ser nulo.

ExemploO campo id_aluno na tabela Aluno. Mesmo que dois alunos tenham o mesmo nome, os IDs serão diferentes.
🔗

Chave Estrangeira (FK)

Campo que cria um relacionamento entre duas tabelas. Aponta para a chave primária de outra tabela.

ExemploO campo id_curso dentro da tabela Matrícula aponta para a PK da tabela Curso, criando o vínculo entre as duas.

Módulo 10

Segurança da Informação em Banco de Dados

Banco de dados pode armazenar dados pessoais, prontuários, senhas e informações financeiras. Segurança não é detalhe — é responsabilidade.

⚠️ Responsabilidade legal No Brasil, a Lei Geral de Proteção de Dados (LGPD – Lei nº 13.709/2018) determina regras claras sobre coleta, armazenamento e tratamento de dados pessoais. Profissionais que trabalham com banco de dados precisam conhecer e aplicar esses princípios.
🔐

Controle de Acesso

Cada usuário deve acessar somente o necessário para sua função. Um aluno vê suas notas; um professor lança notas da sua turma; o gestor acessa relatórios gerais.

🗝️

Senhas Fortes

Senhas longas, com combinação de letras, números e símbolos impedem acessos não autorizados. Nunca use senhas simples como "123456" ou "admin".

👥

Permissões por Perfil

Crie perfis distintos: aluno, professor, gestor, administrador. Cada perfil recebe apenas as permissões necessárias para seu trabalho (princípio do menor privilégio).

📋

Logs de Auditoria

Registros automáticos de todas as ações realizadas: quem acessou, o quê alterou, quando e de onde. Essenciais para identificar abusos e investigar incidentes.

🔒

Criptografia

Protege dados em armazenamento (at rest) e em transmissão (in transit). Senhas devem ser armazenadas com hash (bcrypt, Argon2) — NUNCA em texto puro.

🛡️

Boas Práticas de Uso

Não compartilhar senha, não deixar sessão aberta, desconfiar de links suspeitos (phishing), usar VPN em conexões remotas e manter o SGBD atualizado.

Módulo 11

Backup: a Cópia de Segurança dos Dados

Backup é a garantia de que os dados podem ser recuperados em caso de falha, erro humano, ataque ou desastre. Não é opcional — é obrigatório.

"Quem não tem backup, não tem banco de dados. Tem apenas esperança."
Tipo 01

Backup Completo

Copia todos os dados selecionados de uma vez. É o mais seguro, mas também o que ocupa mais espaço e leva mais tempo.

Tipo 02

Backup Incremental

Copia apenas o que mudou desde o último backup (completo ou incremental). Rápido e econômico em espaço, mas a restauração é mais trabalhosa.

Tipo 03

Backup Diferencial

Copia tudo que mudou desde o último backup completo. Equilíbrio entre completo e incremental: restauração mais simples que o incremental.

Local

Backup Local

Armazenado em dispositivos internos da organização (HD externo, servidor local). Acesso rápido, mas vulnerável a desastres físicos no mesmo local.

Nuvem

Backup em Nuvem

Armazenado em infraestrutura externa (AWS S3, Google Cloud, Azure). Protege contra desastres físicos locais e permite acesso remoto.

⚠️ Crítico

Teste de Restauração

Verificar periodicamente se o backup pode ser efetivamente restaurado. Um backup não testado é uma ilusão de segurança.

🎯 Regra 3-2-1 de backup Mantenha 3 cópias dos dados, em 2 mídias diferentes, com 1 cópia fora do local (offsite ou nuvem). Esta é a estratégia recomendada por especialistas em continuidade de negócios.

Módulo 12

Relatórios: Transformando Dados em Análise

Relatório é uma forma organizada de apresentar informações extraídas do banco. Um bom relatório responde a perguntas de gestão e orienta decisões.

ÁreaExemplo de RelatórioPergunta respondida
🎓 EducaçãoFrequência dos alunos, notas por turma, evasão escolar, desempenho por disciplina.Quais turmas precisam de reforço?
🏥 SaúdeAtendimentos por unidade, vacinas aplicadas, consultas agendadas, filas de espera.Qual unidade está sobrecarregada?
🛒 ComércioProdutos mais vendidos, estoque crítico, vendas por período, clientes ativos.Quais produtos repor com urgência?
💻 TIChamados abertos, finalizados, tempo médio de atendimento, SLA cumprido/perdido.Qual equipe está fora do SLA?

Módulo 14

Glossário Essencial

Os termos técnicos mais importantes que você precisa conhecer para trabalhar com banco de dados.

banco_de_dados
Coleção organizada de dados armazenados para consulta, controle e análise.
SGBD
Sistema Gerenciador de Banco de Dados — software que administra o banco de dados.
tabela
Estrutura composta por linhas (registros) e colunas (campos). Representa uma entidade.
registro
Cada linha de uma tabela. Representa um único elemento da entidade (ex: um aluno).
campo
Cada coluna de uma tabela. Representa uma característica do registro (ex: nome, nota).
SQL
Structured Query Language — linguagem padrão para consultar e manipular bancos relacionais.
chave_primaria (PK)
Campo que identifica de forma única cada registro de uma tabela. Não pode repetir.
chave_estrangeira (FK)
Campo que cria relacionamento entre tabelas, apontando para a PK de outra tabela.
filtro / WHERE
Cláusula SQL usada para selecionar apenas registros que atendem a um critério.
backup
Cópia de segurança dos dados. Essencial para recuperação em caso de falha ou desastre.
relatório
Apresentação organizada de informações extraídas do banco para apoiar decisões.
NoSQL
Modelo de banco de dados flexível, usado em cenários de grande volume e dados variados.
modelagem
Planejamento do banco de dados antes da criação: conceitual, lógico e físico.
integridade
Garantia de que os dados são consistentes, corretos e livres de duplicidades.
índice
Estrutura que acelera consultas ao banco. Como o índice de um livro — facilita encontrar o que você quer.
transação
Conjunto de operações executadas como uma unidade. Ou tudo acontece, ou nada acontece (ACID).

Resumo

O que levar desta aula

Os seis pontos fundamentais que todo profissional de TI precisa internalizar sobre banco de dados.

📊 Dados precisam de organização
Sem organização, não há informação confiável. Dados desorganizados geram decisões erradas, retrabalho e perda de tempo.
⚙️ SGBD gerencia o banco
É o software que permite controle, consulta, segurança e backup. Sem ele, os dados não têm administração adequada.
🔎 SQL consulta dados
A linguagem SQL permite encontrar, inserir, alterar e excluir dados com precisão. É a ferramenta essencial do analista.
📐 Modelagem vem antes
Planejar o banco de dados antes de criar as tabelas evita erros estruturais, retrabalho e problemas de crescimento futuro.
🛡️ Segurança é indispensável
Proteger dados pessoais é responsabilidade legal (LGPD) e ética. Controle de acesso, criptografia e auditoria são essenciais.
💾 Backup precisa ser testado
Fazer backup é obrigatório. Testar a restauração é indispensável. Um backup não verificado pode falhar no momento mais crítico.
