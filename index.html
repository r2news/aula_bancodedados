Módulo 1

De Dado à Decisão: os 4 Pilares

Antes de estudar banco de dados, é preciso entender quatro conceitos que caminham juntos. Esse é o ponto de partida de qualquer profissional de dados.

1
📊
Passo 01
Dado

Registro bruto, isolado, sem contexto suficiente para gerar sentido por si só. É o ponto de partida de tudo, mas sozinho pouco significa.

Exemplo: 8,5 — apenas um número, sem contexto.
2
🔍
Passo 02
Informação

Dado organizado e contextualizado. Quando o dado recebe nome, data, local e relação com outros dados, ele se transforma em informação útil.

Exemplo: Ana tirou 8,5 em Banco de Dados no 1º bimestre.
3
🧠
Passo 03
Conhecimento

Interpretação da informação para entender um padrão ou situação. Aqui começa a análise: comparamos, relacionamos e extraímos sentido.

Exemplo: Ana está bem. Turma tem média 7,2 — acima do esperado.
4
⚡
Passo 04
Decisão

Ação tomada com base no conhecimento produzido. É o destino de todo o processo: dados bem gerenciados levam a decisões mais inteligentes.

Exemplo: Professora propõe atividades avançadas para alunos acima de 8,0.
💡 Exemplo do cotidiano escolar A nota 6,0 é apenas um dado. Quando sabemos que João tirou 6,0 em BD no 1º bimestre, temos informação. Quando percebemos que a maioria tirou entre 5,5 e 6,5, temos conhecimento para decidir se é preciso revisão do conteúdo.
🤔 Pergunta para reflexão Uma empresa consegue tomar boas decisões se seus dados estão incompletos, repetidos, espalhados ou desorganizados? Pense em exemplos da sua vida: quantas decisões erradas já foram tomadas por falta de dados confiáveis?

Módulo 2

O que é Banco de Dados?

Banco de dados está em praticamente tudo que usamos na vida digital. Entender o conceito muda a forma como você enxerga os sistemas.

Banco de dados é uma coleção organizada de dados, armazenada de maneira estruturada, para permitir cadastro, consulta, atualização, análise, proteção e recuperação das informações.

Pode ser algo simples como uma agenda de contatos, ou extremamente complexo como o sistema de um banco digital que processa milhões de transações por segundo.

📌 Definição essencial Banco de dados é a memória organizada dos sistemas. Ele armazena dados de forma estruturada para que pessoas e aplicações possam acessar informações com segurança e rapidez.

Módulo 3

SGBD — Sistema Gerenciador de Banco de Dados

O SGBD é o software que fica "no meio do caminho" entre a aplicação e os dados. Sem ele, não há controle, segurança nem organização.

💡 Ideia-chave O banco de dados guarda as informações. O SGBD gerencia como essas informações serão criadas, acessadas, protegidas, alteradas e recuperadas. Em inglês: DBMS — Database Management System.
🗂️

Criar estruturas

Permite criar tabelas, campos, chaves e relacionamentos. Define como os dados serão organizados antes de qualquer cadastro.

💾

Armazenar dados

Registra os dados de forma organizada, persistente e recuperável, garantindo que nenhuma informação se perca.

🔎

Consultar informações

Permite buscar dados com comandos SQL, filtros, ordenações e relatórios, com alta performance mesmo em grandes volumes.

🔐

Controlar acesso

Define quem pode ver, inserir, alterar ou excluir dados. Garante que cada usuário acesse apenas o que for necessário.

✅

Garantir integridade

Evita inconsistências, duplicidades e registros inválidos. Aplica regras que impedem que dados incorretos entrem no sistema.

🛡️

Executar backup

Permite cópias de segurança automáticas ou programadas, garantindo recuperação em caso de falha, erro ou desastre.

Módulo 4

Modelos de Banco de Dados

Existem diferentes formas de organizar e acessar informações. Conhecer os modelos ajuda o profissional a escolher a estrutura mais adequada para cada projeto.

Mais utilizado

Modelo Relacional

Organiza dados em tabelas compostas por linhas e colunas. Tabelas se conectam por chaves, criando relações entre os dados.

Ideal para: cadastros de alunos, clientes, produtos, notas, vendas e matrículas.
SGBDs: MySQL, PostgreSQL, SQL Server, Oracle.
Flexível

Modelo NoSQL

Armazena dados de forma flexível, sem estrutura rígida. Ideal para dados variados, em grande volume ou com formato imprevisível.

Ideal para: redes sociais, big data, chats e dados em tempo real.
Exemplos: MongoDB, Redis, Firebase.
Histórico

Modelo Hierárquico

Organiza dados em formato de árvore, com relação pai e filho. Um registro "pai" pode ter vários registros "filhos".

Ideal para: estruturas de pastas, organogramas e classificações.
Exemplo real: estrutura de arquivos do Windows/Linux.
Espacial

Modelo Georreferenciado

Armazena dados relacionados à localização espacial e geográfica. Permite consultas por coordenadas e distâncias.

Ideal para: mapas, rotas, fiscalização e planejamento urbano.
Exemplo: PostGIS (extensão do PostgreSQL).
Avançado

Orientado a Objetos

Armazena dados seguindo a lógica de objetos da programação. Integra-se com linguagens OO como Java e Python.

Ideal para: aplicações com estruturas complexas integradas a código OO.
💡 Comparação simples Dados bem estruturados (alunos, cursos, notas) → modelo relacional. Dados variados e de grande volume (posts, logs, chats) → solução NoSQL.

Módulo 5

Modelo Relacional: Tabelas, Linhas e Colunas

O modelo relacional é o mais utilizado no mundo. Para entendê-lo, basta compreender três conceitos simples: tabela, linha e coluna.

📋

TABELA

Representa um assunto principal do sistema (entidade). Exemplos: Alunos, Produtos, Clientes, Pedidos.

↕️

LINHA (Registro)

Cada linha representa um único elemento da entidade. Cada aluno é uma linha; cada produto é uma linha.

↔️

COLUNA (Campo)

Cada coluna representa uma característica/atributo dos elementos. Nome, CPF, nota — cada um é uma coluna.

Módulo 6

SQL — A Linguagem dos Dados

SQL (Structured Query Language) é a linguagem padrão para criar, consultar, alterar e excluir dados em bancos relacionais. É a ferramenta mais importante no dia a dia de quem trabalha com dados.

SELECT
Consultar / ler dadosBusca registros de uma ou mais tabelas. O comando mais utilizado no trabalho diário com dados.
INSERT
Inserir novos dadosAdiciona um novo registro em uma tabela. Usado ao cadastrar um aluno, produto, cliente etc.
UPDATE
Atualizar dados existentesAltera informações já cadastradas, como corrigir uma nota, atualizar um telefone ou mudar o status de um pedido.
DELETE
Excluir registrosRemove registros de uma tabela. Use sempre com WHERE! Operação irreversível se não houver backup.
CREATE
Criar estruturasCria tabelas, bancos de dados, índices e outros objetos. Primeiro passo ao implementar um banco novo.
DROP
Apagar estruturasRemove tabelas ou bancos inteiros. Extremamente cuidado — irreversível! Nunca use sem certeza absoluta.

Exemplos práticos de código SQL

Consultar todos os alunos
-- Retorna TODOS os registros e TODAS as colunas
SELECT *
FROM alunos;

-- Retorna apenas nome, curso e nota
SELECT nome, curso, nota
FROM alunos;

-- Ordenar por nota do maior para o menor
SELECT nome, nota
FROM alunos
ORDER BY nota DESC;
💡 Dica O * significa "todos os campos". Em produção, prefira nomear as colunas explicitamente — é mais eficiente e claro.
Filtrar com WHERE
-- Somente alunos do curso de Banco de Dados
SELECT *
FROM alunos
WHERE curso = 'Banco de Dados';

-- Alunos com nota >= 7,0 (aprovados)
SELECT nome, nota, situacao
FROM alunos
WHERE nota >= 7.0;

-- BD + Noite (dois filtros)
SELECT nome, turno
FROM alunos
WHERE curso = 'Banco de Dados'
  AND turno = 'Noite';
Inserir novo registro
-- Cadastrar um novo aluno
INSERT INTO alunos
  (nome, curso, turno, nota, situacao)
VALUES
  ('Lucas', 'Banco de Dados', 'Manhã',
   8.0, 'Aprovado');

-- Inserindo múltiplos registros de uma vez
INSERT INTO alunos
  (nome, curso, turno, nota, situacao)
VALUES
  ('Marina', 'Redes', 'Tarde',
   7.5, 'Aprovada'),
  ('Pedro', 'Informática', 'Manhã',
   5.0, 'Recuperação');
Atualizar dados existentes
-- Corrigir a nota do aluno com ID = 2
UPDATE alunos
SET nota = 7.5,
    situacao = 'Aprovado'
WHERE id = 2;

-- Aprovar todos com nota >= 7.0
UPDATE alunos
SET situacao = 'Aprovado'
WHERE nota >= 7.0;
⚠️ Atenção críticaSempre use WHERE no UPDATE e no DELETE! Sem WHERE, o comando afeta todos os registros da tabela — erro gravíssimo em produção.
Criar uma tabela do zero
CREATE TABLE alunos (
  id        INT AUTO_INCREMENT
               PRIMARY KEY,
  nome      VARCHAR(100) NOT NULL,
  curso     VARCHAR(80)  NOT NULL,
  turno     ENUM('Manhã','Tarde','Noite'),
  nota      DECIMAL(4,2),
  situacao  VARCHAR(20),
  criado_em TIMESTAMP
               DEFAULT CURRENT_TIMESTAMP
);

-- Tipos mais comuns:
-- INT      → inteiros (id, quantidade)
-- VARCHAR  → texto    (nome, endereço)
-- DECIMAL  → decimais (nota, preço)
-- DATE     → data     (2026-05-28)
-- BOOLEAN  → true / false

Módulo 7

Mecanismos de Filtragem de Dados

Filtrar dados significa selecionar apenas as informações que atendem a um critério específico. Evita trabalho desnecessário e permite análises precisas.

👤 Quais alunos foram aprovados?
WHERE situacao = 'Aprovada'
🌙 Quais alunos estudam à noite?
WHERE turno = 'Noite'
📊 Quais alunos tiraram nota ≥ 7,0?
WHERE nota >= 7.0
🔧 Quais chamados técnicos estão abertos?
WHERE status = 'Aberto'
📅 Vendas de maio de 2026?
WHERE data BETWEEN '2026-05-01' AND '2026-05-31'
🏙️ Clientes de BH ou Ibirité?
WHERE cidade IN ('Belo Horizonte','Ibirité')
🔍 Nomes que começam com "Mar"?
WHERE nome LIKE 'Mar%'
💼 Na prática profissional Uma organização raramente precisa ver todos os dados ao mesmo tempo. Normalmente precisa localizar dados específicos: clientes de uma cidade, alunos de uma turma, produtos com baixo estoque ou chamados abertos. O WHERE é o filtro que torna isso possível.

Módulo 9

Modelagem de Dados

Modelagem é o planejamento do banco antes da criação das tabelas. Como um arquiteto que desenha a planta antes de construir.

"Um bom banco de dados nasce antes do primeiro comando SQL. Ele nasce no planejamento."
1

Modelo Conceitual

Visão geral das principais entidades e seus relacionamentos, sem se preocupar com detalhes técnicos. É a "ideia em alto nível".

ExemploSistema escolar: Aluno, Curso e Matrícula. Um aluno pode estar matriculado em um ou mais cursos.
2

Modelo Lógico

Transformação das ideias em tabelas, campos, chaves e relações. Define a estrutura sem ainda detalhar o SGBD escolhido.

Tabela Aluno: id, nome, turno
Tabela Curso: id, nome, carga_horaria
Tabela Matricula: id, id_aluno, id_curso, data
3

Modelo Físico

Implementação real no SGBD escolhido, com tipos de dados específicos, índices, restrições e comandos SQL reais.

CREATE TABLE aluno (
  id    INT PRIMARY KEY,
  nome  VARCHAR(100),
  turno VARCHAR(10)
);

Chaves Primária e Estrangeira

🔑

Chave Primária (PK)

Campo que identifica de forma única cada registro de uma tabela. Não pode repetir, não pode ser nulo.

ExemploO campo id_aluno na tabela Aluno. Mesmo com nomes iguais, os IDs serão diferentes.
🔗

Chave Estrangeira (FK)

Campo que cria um relacionamento entre duas tabelas. Aponta para a PK de outra tabela.

ExemploO campo id_curso dentro da tabela Matrícula aponta para a PK da tabela Curso.

Módulo 10

Segurança da Informação em Banco de Dados

Banco de dados pode armazenar dados pessoais, prontuários, senhas e informações financeiras. Segurança não é detalhe — é responsabilidade.

⚠️ Responsabilidade legal No Brasil, a LGPD (Lei nº 13.709/2018) determina regras claras sobre coleta, armazenamento e tratamento de dados pessoais. Profissionais que trabalham com BD precisam conhecer e aplicar esses princípios.
🔐

Controle de Acesso

Cada usuário deve acessar somente o necessário para sua função. Aluno vê notas; professor lança; gestor acessa relatórios.

🗝️

Senhas Fortes

Senhas longas com letras, números e símbolos impedem acessos não autorizados. Nunca use "123456" ou "admin".

👥

Permissões por Perfil

Crie perfis distintos: aluno, professor, gestor, administrador. Cada perfil recebe apenas as permissões necessárias (menor privilégio).

📋

Logs de Auditoria

Registros automáticos de todas as ações: quem acessou, o quê alterou, quando e de onde. Essenciais para investigar incidentes.

🔒

Criptografia

Protege dados em armazenamento e transmissão. Senhas devem ser armazenadas com hash (bcrypt) — NUNCA em texto puro.

🛡️

Boas Práticas

Não compartilhar senha, não deixar sessão aberta, desconfiar de links suspeitos (phishing) e manter o SGBD atualizado.

Módulo 11

Backup: a Cópia de Segurança dos Dados

Backup é a garantia de que os dados podem ser recuperados em caso de falha, erro humano, ataque ou desastre.

"Quem não tem backup, não tem banco de dados. Tem apenas esperança."
Tipo 01

Backup Completo

Copia todos os dados selecionados. Mais seguro, mas ocupa mais espaço e leva mais tempo.

Tipo 02

Backup Incremental

Copia apenas o que mudou desde o último backup. Rápido e econômico, mas restauração é mais trabalhosa.

Tipo 03

Backup Diferencial

Copia o que mudou desde o último backup completo. Equilíbrio entre os dois tipos anteriores.

Local

Backup Local

Armazenado em dispositivos internos. Acesso rápido, mas vulnerável a desastres físicos no mesmo local.

Nuvem

Backup em Nuvem

Armazenado externamente (AWS, Google Cloud). Protege contra desastres locais e permite acesso remoto.

⚠️ Crítico

Teste de Restauração

Verificar periodicamente se o backup pode ser efetivamente restaurado. Backup não testado é ilusão de segurança.

🎯 Regra 3-2-1 de backup Mantenha 3 cópias dos dados, em 2 mídias diferentes, com 1 cópia fora do local (offsite ou nuvem). Estratégia recomendada por especialistas em continuidade de negócios.

Módulo 14

Glossário Essencial

Os termos técnicos mais importantes que você precisa conhecer para trabalhar com banco de dados.

banco_de_dados
Coleção organizada de dados armazenados para consulta, controle e análise.
SGBD
Sistema Gerenciador de Banco de Dados — software que administra o banco.
tabela
Estrutura composta por linhas (registros) e colunas (campos). Representa uma entidade.
registro
Cada linha de uma tabela. Representa um único elemento da entidade.
campo
Cada coluna de uma tabela. Representa uma característica do registro.
SQL
Structured Query Language — linguagem padrão para consultar e manipular bancos relacionais.
chave_primaria (PK)
Campo que identifica de forma única cada registro. Não pode repetir nem ser nulo.
chave_estrangeira (FK)
Campo que cria relacionamento entre tabelas, apontando para a PK de outra tabela.
filtro / WHERE
Cláusula SQL para selecionar apenas registros que atendem a um critério.
backup
Cópia de segurança dos dados. Essencial para recuperação em caso de falha.
relatório
Apresentação organizada de informações para apoiar decisões de gestão.
NoSQL
Modelo de banco de dados flexível, usado em cenários de grande volume e dados variados.
modelagem
Planejamento do banco antes da criação: conceitual, lógico e físico.
integridade
Garantia de que os dados são consistentes, corretos e livres de duplicidades.
índice
Estrutura que acelera consultas ao banco. Como o índice de um livro.
transação (ACID)
Conjunto de operações executadas como uma unidade: tudo acontece ou nada acontece.

  1. Quais dados a escola precisa armazenar? Liste as entidades (tabelas) necessárias.
  2. Quais informações precisam aparecer em um relatório para a direção?
  3. Quais filtros SQL seriam úteis para encontrar alunos em risco de reprovação?
  4. Que cuidados de segurança são necessários com esses dados (pense na LGPD)?
  5. Por que o backup seria crítico neste cenário escolar?
  6. Descreva o modelo conceitual com pelo menos 3 entidades e seus relacionamentos.

O que levar desta aula

Os seis pontos fundamentais que todo profissional de TI precisa internalizar sobre banco de dados.

📊 Dados precisam de organização
Sem organização, não há informação confiável. Dados desorganizados geram decisões erradas e retrabalho.
⚙️ SGBD gerencia o banco
É o software que permite controle, consulta, segurança e backup. Sem ele, os dados não têm administração.
🔎 SQL consulta dados
A linguagem SQL permite encontrar, inserir, alterar e excluir dados com precisão. Ferramenta essencial do analista.
📐 Modelagem vem antes
Planejar o banco antes de criar as tabelas evita erros estruturais, retrabalho e problemas de crescimento.
🛡️ Segurança é indispensável
Proteger dados pessoais é responsabilidade legal (LGPD) e ética. Controle de acesso e criptografia são essenciais.
💾 Backup precisa ser testado
Fazer backup é obrigatório. Testar a restauração é indispensável. Backup não verificado pode falhar na hora crítica.
